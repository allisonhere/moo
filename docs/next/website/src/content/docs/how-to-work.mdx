---
title: How to work with Moo
description: Run Moo locally, inside SSH, or through remote attach.
---

Run Moo where the work lives. Attach from wherever you are.

Moo is a background session server plus one or more terminal clients. Panes keep running in the server. Clients attach, detach, and render the session.

## Local work

Start Moo from the project directory:

```bash
moo
```

Moo starts or attaches to your local background session automatically. You do not manage sockets. Run shells, servers, tests, and agents normally inside panes.

Detach the client with `ctrl+b q`. Your panes keep running.

Reattach later:

```bash
moo
```

If you want to end the session and stop its panes, stop the server:

```bash
moo server stop
```

## Remote work through normal SSH

SSH to the machine that has the code and credentials, then run Moo there:

```bash
ssh you@server
moo
```

This works like a terminal multiplexer. Your shell is remote. The Moo server is remote. The agents and panes run on the remote machine. Detach with `ctrl+b q`, disconnect, then SSH back and run `moo` again.

Use this path when you already live inside an SSH shell, when you are on a phone or tablet SSH client, or when you want the simplest setup.

## Work from your phone

Moo works on your phone without a mobile app or web dashboard. Install any SSH client, connect to the machine where your agents run, and start Moo there:

```bash
ssh you@server
moo
```

The same persistent Moo session opens in your phone terminal. The TUI adapts to narrow screens, so you can inspect agents, switch workspaces, and check panes without leaving SSH.

On iPhone, apps like [moshi](https://getmoshi.app/) work well.

## Remote work from your local terminal

Attach through SSH without opening a shell first:

```bash
moo --remote workbox
moo --remote ssh://you@server:2222
```

The remote server keeps the panes running and sends their terminal content and session state over SSH. Your local Moo draws the UI using your local theme and presentation settings.

Use this path when you want the remote session to feel local. The client runs on your machine, so local desktop features such as image clipboard paste can be bridged to the remote server. If you SSH first and run `moo` on the server, Moo runs entirely on that server and cannot read your local desktop clipboard.

For repeat targets, put the host in your SSH config:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

Then attach with:

```bash
moo --remote workbox
```

## Which path to use

Use `moo` for local work. Use `ssh you@server` then `moo` when you want Moo to behave like tmux on that remote shell or when you are using a phone SSH client. Use `moo --remote <host>` for a local UI attached to one remote session, including local clipboard image paste. To keep Local and several SSH machines in one window, save them with `moo machine add <host> --label <label>`; see [Connecting machines](/docs/connecting-machines/).

For remote bootstrap details, named remote sessions, custom binaries, and direct terminal attach, see [Persistence and remote access](/docs/persistence-remote/).
