title: Herdr Forge

Herdr Forge is the temporary name for this downstream development fork. It keeps Herdr's terminal engine, agent detection, provider integrations, session format, and socket API, but runs as a separate application with its own binary, config, state, and sockets. It can sit next to upstream Herdr without either application attaching to the other's server.

:::note
Herdr Forge is a development build, not a published product. The name, install paths, and release process can change. Build it from a reviewed revision you trust.
:::

## Requirements

- A Rust toolchain compatible with the repository. Use the `rust-toolchain`/`Cargo.lock` versions the checkout expects.
- [Zig](https://ziglang.org/download/) 0.16.0 for the vendored libghostty-vt terminal core. Put `zig` on your `PATH`, or set `ZIG=/path/to/zig` before building.
- A terminal emulator with normal ANSI and mouse support. Herdr Forge is a TUI, so it needs a real terminal.
- Linux is the primary development target. macOS and Windows build support is inherited from upstream, but this fork is not yet validated on every platform.

## Build and install

### Release install

From the repository root:

```sh
./scripts/install-herdr-forge.sh
```

The script builds the locked release target with `cargo build --release --locked --bin herdr-forge` and installs `herdr-forge` to `~/.local/bin` by default. Set `HERDR_FORGE_INSTALL_DIR` to choose another binary directory. The script does not edit your shell configuration.

Make sure the install directory is on your `PATH`, then start it:

```sh
herdr-forge
```

### Run from the checkout

For development, run the debug binary directly:

```sh
cargo run --bin herdr-forge
```

or, after a build:

```sh
./target/debug/herdr-forge
```

Debug builds use the `herdr-forge-dev` directories, so they do not share state with a release install or with upstream Herdr.

## Run

Start the TUI where you want to work:

```sh
herdr-forge
```

The first launch creates a config file and onboarding state. Detach with `prefix+q` (the default prefix is `ctrl+b`) and reattach with `herdr-forge`.

Useful commands:

```sh
herdr-forge --version
herdr-forge --help
herdr-forge --default-config
herdr-forge status server --json
herdr-forge workspace list
```

## Separate identity

Herdr Forge keeps upstream's environment variable names, session file format, and socket protocol. Only the application identity and filesystem paths change:

| | Upstream Herdr | Herdr Forge release | Herdr Forge debug |
| --- | --- | --- | --- |
| Binary | `herdr` | `herdr-forge` | `herdr-forge` |
| Config | `~/.config/herdr` | `~/.config/herdr-forge` | `~/.config/herdr-forge-dev` |
| State and logs | `~/.local/state/herdr` | `~/.local/state/herdr-forge` | `~/.local/state/herdr-forge-dev` |
| Default sockets | under the config directory | under the config directory | under the config directory |

The socket file names remain `herdr.sock` and `herdr-client.sock` inside the fork's own config directory. The `HERDR_*` environment names are unchanged so agents, plugins, and integrations continue to work.

Herdr Forge tags panes it launches with `HERDR_PRODUCT_ID=herdr-forge`. If it inherits a socket from a managed pane belonging to another product, it refuses to reuse that socket instead of attaching to an incompatible server.

## What's different

### Command palette

Press `prefix+space` to open the command palette. Type to filter with fuzzy matching, use Up/Down or `j/k` to move, Enter to run the highlighted action, and Esc to close. Built-in actions show their keybindings, and the palette also lists commands advertised by the server, plugins, and popups. The narrow-terminal switcher exposes the same commands in a scrollable menu.

### Agent names in the sidebar

The lower-left agents panel shows the agent name you assigned, then integration-provided display metadata, then the detected agent kind.

To rename an agent:

- Right-click its row in the agents panel and choose **Rename agent**, or **Clear agent name** to remove the override.
- Press `prefix+shift+a` to rename the focused agent. The default binding is configurable as `keys.rename_agent`; set it to `""` to disable it.
- Use the CLI from another terminal:

```sh
herdr-forge agent rename <target> <name>
herdr-forge agent rename <target> --clear
```

Targets accept a unique live agent name or the pane ID that currently hosts the agent. Names must start with a lowercase letter and contain only lowercase letters, digits, `-`, or `_`, up to 32 characters.

A user-assigned name takes precedence over integration-provided display labels, and it is used on the pane border as well. Clearing the name falls back to the integration label or the detected agent kind.

### Remote machines

Remote attach and saved SSH machines discover the fork's own `herdr-forge` binary on the remote host; they never discover or download upstream `herdr`.

- For a same-platform POSIX remote, Herdr Forge installs the local fork binary when the remote copy is missing or older.
- Set `HERDR_REMOTE_BINARY` to an explicit fork binary or package to override the install source.
- Windows remote installation requires an explicit package until fork-owned Windows packages exist. Herdr Forge will not fall back to an upstream Herdr asset.
- SSH authentication, host-key handling, and connection setup are inherited from upstream.

## Configuration

Herdr Forge reads `config.toml` from its own config directory. Print the full default config with:

```sh
herdr-forge --default-config
```

The [config reference](/docs/config-reference/) lists every setting and keybinding. The rest of the upstream documentation applies, with `herdr-forge` in place of `herdr`:

The fork-specific keybinding is:

```toml
[keys]
rename_agent = "prefix+shift+a"
```

## Update

Herdr Forge does not consume upstream Herdr updates. To update, pull a reviewed fork revision and run the install script again:

```sh
git pull
./scripts/install-herdr-forge.sh
```

`herdr-forge update` explains this instead of downloading an upstream binary.

## Remove

Delete the `herdr-forge` binary. Its config and state remain until you explicitly remove the `herdr-forge` or `herdr-forge-dev` directories:

```sh
rm -f ~/.local/bin/herdr-forge
rm -rf ~/.config/herdr-forge ~/.local/state/herdr-forge
```

Removing the fork does not touch upstream Herdr data.

## Troubleshooting

### `zig executable not found`

Install Zig 0.16.0 and put it on `PATH`, or point the build at it:

```sh
ZIG=/path/to/zig cargo build --release --locked --bin herdr-forge
```

### `refusing to use a Herdr socket inherited from another product`

You launched Herdr Forge inside a managed pane belonging to another product, such as upstream Herdr. Start it from a normal terminal instead. If you intentionally want to bypass the inherited socket, clear the relevant variables:

```sh
env -u HERDR_ENV -u HERDR_PRODUCT_ID \
    -u HERDR_SOCKET_PATH -u HERDR_CLIENT_SOCKET_PATH \
    herdr-forge
```

### Nested Herdr is blocked

Run outside the other Herdr session, or opt in explicitly in the fork config:

```toml
[experimental]
allow_nested = true
```

### `herdr-forge: command not found`

Add the install directory to your `PATH`, for example `~/.local/bin`.

### Remote setup or Windows attach fails

Set `HERDR_REMOTE_BINARY` to a compatible fork binary or package for the target machine. Windows remote installs are not available without an explicit package.

### Logs

Find the server log in the fork's config directory, for example `~/.config/herdr-forge/herdr-server.log`.

## Development

Use the repository recipes:

```sh
export ZIG=/path/to/zig
just test
just check
```

`just test` runs the Rust suite plus the repository contract tests. `just check` also runs formatting and the broader checks. The full toolchain expects `just`, `cargo-nextest`, and `bun`; the Windows cross-lint additionally needs `just setup-windows-cross` once to download the Microsoft SDK.

The fork adds no telemetry, cloud account, or network dependency of its own. It uses the network only for the agent providers and remote machines you configure.

## Current limitations

- The name **Herdr Forge** is temporary while product branding is undecided.
- There are no fork-owned release downloads, update channel, or remote packages yet. POSIX remotes seed the local fork binary; Windows remotes need an explicit package.
- The larger agent workspace features are still in progress: a unified agent dashboard, attention queue, activity history, and multi-agent orchestration are not part of this build.
